\textbf{Reference without human labels.} Human labeling was not carried out for this submission, and no model output
substitutes for it. Accuracy is therefore reported only where P1 alone fixes the label: \NPD{} cases in which one
instruction's file is not on the target's directory chain, so that instruction is not loaded and the label is
\emph{Disjoint applicability}. They are \NPDOrig{} mined originals (all unrelated-branch pairs), \NPDVar{} constructed
target-path variants, and \NPDCtrl{} order controls. B2 computes the loaded set in code, so on these cases it is correct
by construction unless its extraction reports insufficient evidence or fails; the open question is whether B1 and B0
also get them right. All other measures in Table~\ref{tab:results} need no reference. This analysis was defined and
frozen by hash before the sealed predictions were opened; the repeat comparison below was added afterwards and is
exploratory.

\textbf{Directory scope (RQ2, determined subset).} B1, B2, and B1R labeled all \NPD{} profile-determined cases
correctly, the \NPDMain{} originals and variants as well as the \NPDCtrl{} controls (\PrimaryBTwoOnly{} cases favored
B2 and \PrimaryBOneOnly{} favored B1). B1's explanation or cited evidence named the off-chain file in
\BOnePDCitesOffChain{} of the \NPDMain{} cases, so the direct model handled directory applicability from the paths and
the profile text without a deterministic step. B0, which ignores scope, flagged \BZeroPDFalseConf{} of the \NPD{} cases
as conflicts: one ESM/CommonJS keyword match between two unrelated packages, in the original and in its order control.
For this model, the determined subset does not support the hypothesis that explicit structure is needed to handle
directory scope.

\textbf{Label-free comparison.} No model arm labeled any original or variant an unresolved conflict or a valid override;
every such prediction was \emph{Compatible} or \emph{Disjoint} (Fig.~\ref{fig:labels}), while B0 flagged
\BZeroCalledConfAnn{} of the 54. (The only \emph{Valid override} in the study is B1R's single self-review change, on an
order control.) The challenge-oriented retrieval thus surfaced lexically similar pairs that the models judged
non-conflicting. The arms differ on the boundary between compatibility and condition-limited applicability: on originals
B2 chose \emph{Disjoint} \BTwoDistOrigDisjoint{} times and B1 \BOneDistOrigDisjoint{} times, and B1 and B2 agreed on
\AgreeBOneBTwoOrigSame{} of 27 originals (Cohen's $\kappa = \AgreeBOneBTwoOrigKappa$) and \AgreeBOneBTwoVarSame{} of 27
variants ($\kappa = \AgreeBOneBTwoVarKappa$). The first non-determined original on which they disagree (by the declared
selection rule) pairs a root rule ``use \texttt{Protocol} for decoupling'' with a nested rule ``avoid
\texttt{TYPE\_CHECKING}'', both naming Python constructs, for a TypeScript target. B1 treated both rules as inactive,
whereas B2's extraction found no explicit condition and returned \emph{Compatible}; on the order control of the same
case the two arms swapped answers. Whether the rules apply is a judgment about implicit applicability that P1 does not
settle and that human labels must resolve.

\textbf{Stability and sensitivity (RQ3).} Swapping the order of the two instructions changed the label in four of
\NControls{} controls for each model arm (\BOneOrderStable{}, \BTwoOrderStable{}, and \BOneROrderStable{} unchanged for
B1, B2, and B1R), although all \NPDCtrl{} determined controls stayed correct. These changes must be read against
run-to-run variation: B1R's first call repeats B1's request exactly (same prompt, evidence, and seed, but on the updated
runtime), yet its label differed from B1's in \RepeatDiffTotal{} of 81 cases (\RepeatDiffOrig{} originals,
\RepeatDiffVar{} variants, \RepeatDiffCtrl{} controls), a margin as large as the order effects and the B1--B2
disagreements. All \NVarTarget{} target-path variants, which move the target out of the nested file's directory, were
labeled \emph{Disjoint} by every arm; the label differed from the original's in \BOneTVChanged{} (B1), \BTwoTVChanged{}
(B2), and \BOneRTVChanged{} (B1R) cases, because many originals were already judged inactive by condition. Placement
variants changed B2's label once and B1's \BOnePVChanged{} times out of \NVarPlacement{}; without reference labels, and
given the run-to-run variation, we cannot say which changes are correct.

\textbf{Cost.} No arm had a failure, retry, or malformed output. B2 averaged \BTwoCallsPerCase{} calls and
\BTwoMeanOut{} output tokens per case, against \BOneCallsPerCase{} and \BOneMeanOut{} for B1; the equal-call control B1R
(\BOneRMeanOut{} tokens) changed its first answer in \BOneRReviewChanged{} of 81 cases, so its differences from B1 come
mainly from resampling rather than review. Latency is not compared because the GPU was shared with another process for
part of the runs.
